Usage Guide

A compact flow for adding, logging in, and switching accounts.

Workflow

1

Create a profile

Create a backup folder before binding an account.

2

Log in

Use the current profile login action to refresh the local account state.

3

Switch safely

Use the profile cards to switch while preserving the previous account backup.

4

Refresh quota

Use Refresh when a card looks stale. It reads quota data without starting a model run, but it still performs a network request.

5

Set a custom Base URL (optional)

Use a custom Base URL only for API key profiles that point at a compatible endpoint.

6

Where backups live

The account_backup folder under CODEX_HOME stores one folder per profile with auth and profile metadata.

Tips & warnings

Refresh cadence

Local quota is read every 15 seconds. Silent active refresh waits at least 5 minutes, and bulk plan refresh runs on startup or local-day rollover with a 6-hour freshness skip.

Base URL applies to API key profiles

ChatGPT/OAuth profiles may keep a Base URL note, but Windows clears root config before using them.

Switching preserves saved accounts

Switch publishes the selected profile into the live Codex home and leaves other account_backup slots intact.

FAQ

When do quota numbers reset?

Reset times come from Codex and ChatGPT rate-limit windows when the service returns them.

Login fails or Codex CLI is missing?

Open Settings and choose the real codex executable. Edge-marked profiles use the app-server browser login path.

Switch keeps spinning or says it is locked?

A .switch.lock file prevents concurrent writes and is released when the operation finishes; stale locks are cleaned automatically.

Where is account data stored?

Each profile lives under CODEX_HOME/account_backup. Copy that folder for an external backup and protect exported auth files.
